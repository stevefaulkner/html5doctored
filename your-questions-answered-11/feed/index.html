]]> By: Brian Campbell http://html5doctor.com/your-questions-answered-11/#comment-10016 Tue, 03 Aug 2010 06:32:03 +0000 http://html5doctor.com/?p=2328#comment-10016 You say “it is now explicitly permitted to omit all kinds of tags” as if this is a new feature in HTML5; but in fact, it was perfectly valid in HTML 4 to omit these tags as well. For instance, from HTML 4: “The HEAD Element … Start tag: optional, End tag: optional”. You can check this out by running a document containing just the HTML 4 doctype, an empty <title> element (which is still required; it’s the only mandatory tag in an HTML document), and an opening <p> tag (in HTML 4, it was required that the body not be empty, and this is the easiest way to ensure that) through an HTML 4 validator, and it will come back valid.

For a few more tips on going all the way when minifying HTML, see Anne van Kesteren’s Optimizing Optimizing HTML.

]]> By: Alohci http://html5doctor.com/your-questions-answered-11/#comment-9984 Sat, 31 Jul 2010 00:55:21 +0000 http://html5doctor.com/?p=2328#comment-9984 @Oli – It’s not the HTML, HEAD and BODY *elements* that are allowed to be omitted, it’s the *tags*. The elements are inferred and created by the parser. And those inferences are not part of the error handling, at least in HTML5 (i.e. they don’t cause a parse error). I don’t know if browsers internally treat them as an error, but theoretically at least they’re not part of the error handling.
